# Contextual compute and the OS

Status: `proposed`. The full argument is in [the Loom note](https://github.com/siliconcordat/loom/blob/main/docs/08-contextual-compute.md). This file states only what Layer 3 owns. It does not change `warp-modeld`, the sandbox, or the recovery image.

Warp is the body the somatic computer lives in. An ancillary hub sets a parameter field before a task runs. Pathways that field leaves closed are not mounted. The cloud model does its heavy work only inside the open set.

The static shell stays resident. Recovery, the load gate, and the ports a dynamic piece may use do not move when a session changes taste. Dynamic pieces swap inside that shell. One template still compiles a lightweight client and a power host. Those are two hardware renders, not two architectures.

A closed adapter is not loaded and then ignored. `warp-modeld` remains fail-closed for anything that does load. This note adds no load stage. The falsifier for the closed-set rule is in the Loom note.
